# Plan: Vendor ponytail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ponytail is vendored unchanged in `plugins/shared/ponytail/`, a weekly sync PR brings each upstream release
with its notes, existing installs move over on their next update, and ponytail's band is the only band.

**Architecture:** A sync script in the existing `sync-lib.mjs` pattern clones upstream at its newest stable tag,
copies the Claude Code parts and writes a PR body file; a workflow validates and opens the PR. Our two `AbovePrompt`
hooks are deleted. No installer code changes; Claude Code's update moves existing installs (verified in Task 4).

**Tech Stack:** Node 22 ESM, stdlib only, `node:test`; GitHub Actions with `peter-evans/create-pull-request` and `gh`;
Claude Code mods (`claude plugin test`/`validate`).

**Spec:** `docs/superpowers/specs/2026-10-20-ponytail-v5-design.md`; flow state in `docs/features/ponytail-v5/flow.md`.

## Global Constraints

- Node standard library only; no npm dependencies.
- One version: vendored `plugin.json` carries `package.json`'s version (now `0.4.0`); never bump by hand.
- Vendored files are never hand-edited; only the sync script writes `plugins/shared/ponytail/`.
- Upstream's stable `vX.Y.Z` tags only, never main.
- Vendor only what the Claude Code plugin needs: no README, assets, other hosts, upstream tests.
- No tests of ours for upstream's code; our sync logic gets one test file.
- Commit messages are one sentence; no co-author lines (rules.md).
- Branch `feat/ponytail-v5` from current `origin/main`, one commit per task. Close the bot's "Pin ponytail to v5.3.2"
  PR once ours is open (user).

## Review Focus

1. A tag range where tags have no GitHub release or `gh` is missing: notes fall back to labelled commit subjects;
   a tag with neither shows "(no changes)". Task 3 tests.
2. Upstream adds a file or a manifest component: `hooks/` is copied whole (new files land), and an unknown
   `plugin.json` key or default component folder makes the sync fail; the workflow runs `check-repo` with Claude Code
   installed. Task 2 test + Task 3 workflow.
3. Upstream text in our PR: `#123` links and `@mentions` point at upstream / are inert. Task 3 test.
4. No old tag (missing `UPSTREAM`, untagged sha) or a newest tag older than the vendored one: newest release's notes
   only, no compare link / `fail()`. Task 3 tests.
5. A failed or partial clone never leaves `plugins/shared/ponytail/` half-deleted: everything is checked against the
   clone before the folder is replaced. Task 2 step.
